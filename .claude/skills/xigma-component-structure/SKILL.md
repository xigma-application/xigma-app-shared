# xigma-app-shared Component Structure

Ported from `xigma-app`'s `xigma-component-structure`. This repo has no `pages/` (it's a component
library, not an app with routes) — everything below applies to `packages/components/src/<Name>/`
only. `constant/colors.ts` and the `pages/` example paths mentioned below are `xigma-app`-specific;
this repo doesn't have them yet — see the note under "Styles" for what to do here instead.

## Folder shape

One folder per component, PascalCase, named identically to the default export. The `.tsx`/`.spec.tsx`
files match that PascalCase name, but **the `.module.scss` file is kebab-case** — this is easy to
miss because single-word components (`App.module.scss`) look identical either way, but it's
confirmed unambiguously across every multi-word component in `xigma-app`: `mouse-modes.module.scss`
(`MouseModes/`), `tool-dropdown.module.scss` (`ToolDropdown/`), `popover-item.module.scss`,
`popover-separator.module.scss`, `icon.module.scss` (`Icon/`) — every single multi-word
`.module.scss` there is kebab-case, zero exceptions.

```
packages/components/src/MouseModes/
  MouseModes.tsx
  mouse-modes.module.scss
  MouseModes.spec.tsx
  snapshots/
    MouseModes.spec.tsx.snap   (generated by Vitest, once this repo has a test runner configured)
```

See [[xigma-module-structure]] for how `types.ts`/`constants.ts`/`utils/` join this shape once a
component grows beyond a single file.

## The component file

```tsx
import { FC } from 'react';

// styles
import styles from './component-name.module.scss';

const ComponentName: FC<TComponentNameProps> = (props) => (
  <div className={styles.ComponentName}>...</div>
);

export default ComponentName;
```

- `FC` from `react`, arrow function, PascalCase matching the folder/file name.
- **Both** a named export (`export const ComponentName`) when other files need the type/reference
  directly, **and always** `export default ComponentName` at the bottom — this is what lets
  `packages/components/src/index.ts` do `export * from './MouseModes/MouseModes'` and still expose
  a usable named binding.
- Props type is `TComponentNameProps` (the `T` prefix + PascalCase name convention).

## Styles: CSS Modules, not global classes

Every component imports its own `.module.scss` and reads classes off the `styles` object —
`className={styles.ComponentName}`. The top-level class inside the file matches the component name
exactly (`.App`, `.Icon`), sub-elements get their own PascalCase class. Colors are never
hardcoded — always the CSS custom properties from [[xigma-theming]]
(`background-color: var(--color-neutral-4);`), so components repaint automatically on theme change
with zero JS.

When a color is needed as a **prop value** rather than in `.module.scss` (e.g. an inline `style`, or
passed into a child component), `xigma-app` pulls it from `constant/colors` instead of writing
`var(--color-*)` by hand. This repo doesn't have that file yet — if `@xigma/components` grows enough
prop-level color usage to need it, it belongs in `@xigma/scss` or `@xigma/utils` (TBD, ask before
picking one), not duplicated per consuming app.

## Tests

Co-located `ComponentName.spec.tsx`, not a separate `__tests__` folder — see
[[xigma-test-conventions]] for the `describe`/`it` naming and step-comment convention used inside
it, and [[xigma-import-order]] for how the imports at the top of both the component and its spec
are grouped. This repo doesn't have a test runner wired up yet (`xigma-app` uses Vitest) — set one
up before relying on this section literally.
