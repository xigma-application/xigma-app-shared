# xigma-app-shared Component Structure

Ported from `xigma-app`'s `xigma-component-structure`. This repo has no `pages/` (it's a component
library, not an app with routes) — everything below applies to `packages/components/src/<Name>/`
only.

## Folder shape

One folder per component, PascalCase, named identically to the default export. The `.tsx`/`.spec.tsx`
files match that PascalCase name. `xigma-app` uses kebab-case `.module.scss` filenames — that part
does **not** carry over as-is, see "Styles" below for why and what this repo actually uses instead.

```
packages/components/src/MouseModes/
  MouseModes.tsx
  mouse-modes.scss
  MouseModes.spec.tsx
  snapshots/
    MouseModes.spec.tsx.snap   (generated by Vitest, once this repo has a test runner configured)
```

See [[xigma-module-structure]] for how `types.ts`/`constants.ts`/`utils/` join this shape once a
component grows beyond a single file.

## The component file

```tsx
import { FC } from 'react';

// styles
import './component-name.scss';

const ComponentName: FC<TComponentNameProps> = (props) => (
  <div className="ComponentName">...</div>
);

export default ComponentName;
```

- `FC` from `react`, arrow function, PascalCase matching the folder/file name.
- **Both** a named export (`export const ComponentName`) when other files need the type/reference
  directly, **and always** `export default ComponentName` at the bottom — this is what lets
  `packages/components/src/index.ts` do `export * from './MouseModes/MouseModes'` and still expose
  a usable named binding.
- Props type is `TComponentNameProps` (the `T` prefix + PascalCase name convention).

## Styles: plain global `.scss`, not CSS Modules — verified while porting `Icon`

`xigma-app` uses CSS Modules (`className={styles.ComponentName}`, filename `component-name.module.scss`).
That does **not** work here and was not a style preference — it's a hard build constraint,
confirmed while porting `Icon` (see [[xigma-icons]] for the full story): `@xigma/components` is
built once with `tsup`/esbuild, which has no CSS-Modules support (unlike Vite, which Storybook
uses). Naming a file `*.module.scss` while the tsup build treats it as plain CSS would make
Storybook silently hash the class names while the shipped package doesn't — a real dev/build
divergence, not just a style nit.

So in this repo:

- Style files are named `component-name.scss` — **no** `.module.` infix, kebab-case, one per
  component folder.
- Root class is the plain, unscoped PascalCase component name (`.Icon`, `.MouseModes`), matched by
  a literal string in JSX (`className="Icon"`), not an object lookup. Sub-elements follow
  [[xigma-scss-bem]] (`&__element`), which already assumes real global CSS and needs no change.
- Import the stylesheet for its side effect only: `import './component-name.scss';` — no `styles`
  binding to import, since there's nothing to look up.
- Colors are never hardcoded — always the CSS custom properties from [[xigma-theming]]
  (`background-color: var(--color-neutral-4);`), so components repaint automatically on theme
  change with zero JS. This part is unchanged from `xigma-app`.
- For a color needed as a **prop value** rather than in `.scss` (inline `style`, or passed into a
  child component), pull it from `packages/components/src/colors.ts` (ported from `xigma-app`'s
  `constant/colors.ts`, re-exported from the package root) instead of writing `var(--color-*)` by
  hand — see `Icon.tsx`'s `colors[color]` for the pattern.
- `@xigma/scss`'s mixins that emit `:global(...)` (`svg-color`, `disabled` — written for
  CSS-Modules consumers) need their `:global()` stripped after compiling in both this repo's own
  build pipelines; see [[xigma-icons]] for exactly where that happens. Don't fork the mixins
  themselves — they're correct as-is for `xigma-app`/x-design.

## Tests

Co-located `ComponentName.spec.tsx`, not a separate `__tests__` folder — see
[[xigma-test-conventions]] for the `describe`/`it` naming and step-comment convention used inside
it, and [[xigma-import-order]] for how the imports at the top of both the component and its spec
are grouped. This repo doesn't have a test runner wired up yet (`xigma-app` uses Vitest) — set one
up before relying on this section literally.
